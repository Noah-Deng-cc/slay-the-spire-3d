## 1. 核心玩法循环

```
┌──────────────────────────────────────────────────┐
│                                                  │
│   🗺️ 地图层 (Roguelike Map)                      │
│   ┌─────┐    ┌─────┐    ┌─────┐                 │
│   │战斗 │───▶│商店 │───▶│随机 │───▶ ... ───▶ 🏆Boss│
│   │节点 │    │节点 │    │事件 │                 │
│   └─────┘    └─────┘    └─────┘                 │
│      │                                               │
│      ▼                                               │
│   ⚔️ 战斗层 (Combat)                               │
│   ┌──────────┐  ┌──────────┐                       │
│   │  抽牌阶段  │  │  出牌阶段  │                       │
│   │  每回合5张  │─▶│  消耗能量  │─▶ 重复 ──▶ 💀/🎉      │
│   │  能量3点   │  │  造成伤害  │                       │
│   └──────────┘  └──────────┘                       │
│                                                  │
└──────────────────────────────────────────────────┘
```

**一句话描述**: 玩家选择路线爬塔 → 遭遇战斗/事件/商店 → 构筑卡组 → 击败最终Boss

## 2. 卡牌系统 (核心)

### 2.1 卡牌数据结构

```csharp
public class CardData
{
    public string Id;              // 唯一ID, 如 "strike_01"
    public string Name;            // 卡牌名, 如 "斩击"
    public int Cost;               // 能量消耗 (0-5)
    public CardType Type;          // 攻击/技能/能力
    public CardRarity Rarity;      // 普通/罕见/稀有
    public string Description;     // 效果描述
    public CardEffect[] Effects;   // 实际效果列表
    public Sprite Artwork;         // 卡面立绘
    public ElementType Element;    // 元素属性 (米家特色!)
}

public enum CardType    { Attack, Skill, Power }
public enum CardRarity  { Common, Uncommon, Rare }
public enum ElementType { None, Fire, Ice, Thunder, Wind, Quantum }
```

### 2.2 效果系统 (命令模式)

```csharp
// 每种效果是一个可组合的"效果块"
public abstract class CardEffect
{
    public EffectTarget Target;    // 目标: 敌方/自己/全体
    public int Value;              // 数值

    public abstract void Execute(CombatState state);
}

// 示例效果:
// - DealDamage    : 造成 X 点伤害
// - GainBlock     : 获得 X 点护盾
// - DrawCards     : 抽 X 张牌
// - ApplyBuff     : 施加 X 层buff
// - AoeDamage     : 全体造成 X 点伤害
// - HealHp        : 恢复 X 点生命
```

## 3. 战斗系统

### 3.1 战斗状态机

```
                    ┌──────────┐
                    │ 战斗开始  │
                    └────┬─────┘
                         ▼
              ┌──────────────────┐
         ┌───▶│   玩家回合开始    │
         │    └────────┬─────────┘
         │             ▼
         │    ┌──────────────┐
         │    │  抽牌阶段     │ ← 抽满5张，能量回满(3)
         │    └──────┬───────┘
         │           ▼
         │    ┌──────────────┐
         │    │  出牌阶段     │ ← 玩家操作，扣能量，结算效果
         │    └──────┬───────┘
         │           ▼
         │    ┌──────────────┐
         │    │  结束回合?    │
         │    └──┬───────┬───┘
         │   是  │       │ 否 → 回到出牌阶段
         │       ▼       │
         │    ┌──────────────┐
         │    │  弃牌 + buff结算│
         │    └──────┬───────┘
         │           ▼
         │    ┌──────────────┐
         │    │  敌人回合     │ ← AI出招，结算伤害
         │    └──────┬───────┘
         │           ▼
         │    ┌──────────────┐
         │    │  检查胜负     │
         │    └──┬───┬───┬──┘
         │  胜   │  败  │ 继续
         │   ▼   │   ▼  │  └──▶ 回到玩家回合
         │  🎉   │  💀  │
         └───────┴──────┘
```

### 3.2 战斗数值

```
玩家:
  HP: 80/80         (生命值)
  Energy: 3/3       (每回合恢复)
  Block: 0          (护盾，回合开始清零)
  Strength: 0       (力量，增加攻击伤害)

敌人:
  HP: 50/50
  Intent: "攻击 8点"  (下回合意图可见!)
  Buffs: []

战斗流程:
  1. 玩家回合 → 抽5张 → 出牌(消耗能量) → 结束回合
  2. 护盾清零 → Buff/debuff触发
  3. 敌人按Intent行动 → 先扣护盾再扣HP
  4. 检查胜负 → 玩家回合
```

## 4. Roguelike地图系统

### 4.1 地图结构

```
         [起点]
          /  \
       [战斗] [商店]
       /   \    |
    [篝火] [事件] [战斗]
       \   |   /
       [精英怪]
           |
        [Boss]
```

- 每层(Act) 8-12个节点
- 3层 + 最终Boss
- 节点类型: 战斗(70%) / 商店(10%) / 篝火(10%) / 随机事件(10%)
- 玩家只能向前/斜向移动

### 4.2 节点类型

| 节点 | 效果 |
|------|------|
| ⚔️ 战斗 | 普通敌人，掉落金币+选1张牌 |
| 🛒 商店 | 花金币买牌/遗物/药水，可删牌 |
| 🔥 篝火 | 恢复30%HP 或 升级一张牌 |
| ❓ 事件 | 随机剧情事件，多种选项 |
| 💀 精英 | 强敌，掉落稀有遗物 |
| 👑 Boss | 层末Boss，解锁下一层 |

## 5. 米家风格特征

### 5.1 视觉
- **Cel Shading**: 卡通渲染 + 描边
- **元素色彩**: 火=橙红 / 冰=蓝白 / 雷=紫 / 风=绿
- **粒子特效**: 出牌/攻击/受击华丽的粒子爆发
- **卡面立绘**: AI生成的二次元风格插画

### 5.2 元素反应系统 (特色卖点!)

```
火 + 冰 = 融化 (伤害×1.5)
火 + 雷 = 超载 (追加AOE)
冰 + 雷 = 超导 (减防)
风 + 任意 = 扩散 (全体施加元素)
```

→ 鼓励玩家在不同卡牌间组合元素反应，增加策略深度

### 5.3 UI风格
- 半透明科技感面板
- 圆角 + 发光边框
- 流畅的卡牌划入/打出动画

## 6. MVP范围界定 (第1个月目标)

### ✅ MVP必做:
- [ ] 15张卡牌 + 效果系统
- [ ] 1个可玩角色 (初始卡组10张)
- [ ] 3种普通敌人 + 1个Boss
- [ ] 完整的战斗状态机
- [ ] 基础地图 (线性8节点/层)
- [ ] 商店 + 篝火节点
- [ ] 2种药水 + 3种遗物
- [ ] 1层可玩到通关
- [ ] 3D战斗场景 (URP + cel shading)
- [ ] 卡牌3D化 (卡片带厚度/翻转效果)

### ❌ MVP不做 (后续迭代):
- 多角色
- 完整3层
- 存档系统
- 音效/BGM
- 完整动画系统
- 多语言

### 🎯 MVP完成标准:
> 一个陌生人下载后，能够从启动 → 爬塔 → 战斗 → 通关Boss，全程无crash

## 8. 关键设计模式应用

| 模式 | 应用场景 | 面试可讲 |
|------|----------|----------|
| **命令模式** | 卡牌效果系统 | 解耦卡牌定义与效果执行 |
| **状态模式** | 战斗状态机 | 回合状态转换 |
| **观察者模式** | 事件系统(出牌/受伤) | UI更新、buff触发 |
| **对象池** | 卡牌GameObject复用 | 性能优化 |
| **单例模式** | GameManager, AudioManager | 全局管理 |
| **工厂模式** | 卡牌/敌人/节点生成 | 灵活创建对象 |

> 💡 **面试TIP**: 每种设计模式你都能讲出在SS3D里具体怎么用的，这就是最好的项目答辩。

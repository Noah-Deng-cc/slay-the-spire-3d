## 1. 核心玩法循环

```
┌──────────────────────────────────────────────────┐
│                                                  │
│   🗺️ 地图层 (Roguelike Map)                      │
│   ┌─────┐    ┌─────┐    ┌─────┐                 │
│   │战斗 │───▶│商店 │───▶│随机 │───▶ ... ───▶ 🏆Boss│
│   │节点 │    │节点 │    │事件 │                 │
│   └─────┘    └─────┘    └─────┘                 │
│      │                                               │
│      ▼                                               │
│   ⚔️ 战斗层 (Combat)                               │
│   ┌──────────┐  ┌──────────┐                       │
│   │  抽牌阶段  │  │  出牌阶段  │                       │
│   │  每回合5张  │─▶│  消耗能量  │─▶ 重复 ──▶ 💀/🎉      │
│   │  能量3点   │  │  造成伤害  │                       │
│   └──────────┘  └──────────┘                       │
│                                                  │
└──────────────────────────────────────────────────┘
```

**一句话描述**: 玩家选择路线爬塔 → 遭遇战斗/事件/商店 → 构筑卡组 → 击败最终Boss

## 2. 卡牌系统 (核心)

### 2.1 卡牌数据结构

```cpp
// 运行时卡牌数据；正式实现放在 Source/SS3D/CombatTypes.h
USTRUCT(BlueprintType)
struct FCardData
{
    GENERATED_BODY()

    FName Id;
    FText Name;
    int32 Cost = 1;
    ECardType Type;
    ECardRarity Rarity;
    FText Description;
    TArray<FCardEffect> Effects;
    TObjectPtr<UTexture2D> Artwork;
    EElementType Element;
}

UENUM(BlueprintType) enum class ECardType : uint8 { Attack, Skill, Power };
UENUM(BlueprintType) enum class ECardRarity : uint8 { Common, Uncommon, Rare };
UENUM(BlueprintType) enum class EElementType : uint8 { None, Fire, Ice, Thunder, Wind, Quantum };
```

### 2.2 效果系统 (命令模式)

```cpp
// 每种效果是一个可组合的"效果块"
USTRUCT(BlueprintType)
struct FCardEffect
{
    GENERATED_BODY()
    EEffectTarget Target;
    int32 Value = 0;
    ECardEffectType Type;
}

// 示例效果:
// - DealDamage    : 造成 X 点伤害
// - GainBlock     : 获得 X 点护盾
// - DrawCards     : 抽 X 张牌
// - ApplyBuff     : 施加 X 层buff
// - AoeDamage     : 全体造成 X 点伤害
// - HealHp        : 恢复 X 点生命
```

## 3. 战斗系统

### 3.1 战斗状态机

```
                    ┌──────────┐
                    │ 战斗开始  │
                    └────┬─────┘
                         ▼
              ┌──────────────────┐
         ┌───▶│   玩家回合开始    │
         │    └────────┬─────────┘
         │             ▼
         │    ┌──────────────┐
         │    │  抽牌阶段     │ ← 抽满5张，能量回满(3)
         │    └──────┬───────┘
         │           ▼
         │    ┌──────────────┐
         │    │  出牌阶段     │ ← 玩家操作，扣能量，结算效果
         │    └──────┬───────┘
         │           ▼
         │    ┌──────────────┐
         │    │  结束回合?    │
         │    └──┬───────┬───┘
         │   是  │       │ 否 → 回到出牌阶段
         │       ▼       │
         │    ┌──────────────┐
         │    │  弃牌 + buff结算│
         │    └──────┬───────┘
         │           ▼
         │    ┌──────────────┐
         │    │  敌人回合     │ ← AI出招，结算伤害
         │    └──────┬───────┘
         │           ▼
         │    ┌──────────────┐
         │    │  检查胜负     │
         │    └──┬───┬───┬──┘
         │  胜   │  败  │ 继续
         │   ▼   │   ▼  │  └──▶ 回到玩家回合
         │  🎉   │  💀  │
         └───────┴──────┘
```

### 3.2 战斗数值

```
玩家:
  HP: 80/80         (生命值)
  Energy: 3/3       (每回合恢复)
  Block: 0          (护盾，回合开始清零)
  Strength: 0       (力量，增加攻击伤害)

敌人:
  HP: 50/50
  Intent: "攻击 8点"  (下回合意图可见!)
  Buffs: []

战斗流程:
  1. 玩家回合 → 抽5张 → 出牌(消耗能量) → 结束回合
  2. 护盾清零 → Buff/debuff触发
  3. 敌人按Intent行动 → 先扣护盾再扣HP
  4. 检查胜负 → 玩家回合
```

## 4. Roguelike地图系统

### 4.1 地图结构

```
         [起点]
          /  \
       [战斗] [商店]
       /   \    |
    [篝火] [事件] [战斗]
       \   |   /
       [精英怪]
           |
        [Boss]
```

- 每层包含 8 行：起点、6 行分支节点和层末 Boss
- 每行生成 2-3 个节点，节点总数由随机种子决定
- 3层，每层都有一个层末 Boss；第三层 Boss 即为最终 Boss
- 节点类型: 战斗 / 奖励 / 商店 / 休息 / 事件 / 精英 / Boss
- 玩家只能向前/斜向移动

### 4.2 节点类型

| 节点 | 效果 |
|------|------|
| ⚔️ 战斗 | 普通敌人，掉落金币+选1张牌 |
| 🛒 商店 | 花金币买牌/遗物/药水，可删牌 |
| 🔥 篝火 | 恢复30%HP 或 升级一张牌 |
| ❓ 事件 | 随机剧情事件，多种选项 |
| 💀 精英 | 强敌，掉落稀有遗物 |
| 👑 Boss | 层末Boss，解锁下一层 |

## 5. 表现与后续差异化

### 5.1 视觉
- **2D UI**: 地图、卡牌、资源、商店和节点操作
- **3D 战斗**: 角色、敌人、攻击、受击和技能演出
- **UE5 表现**: 后续加入模型、动画、材质、粒子和音频
- **纯代码基线**: 当前先通过 GameMode 日志完整验证玩法闭环

### 5.2 后续差异化系统（不属于当前 MVP）

```
火 + 冰 = 融化 (伤害×1.5)
火 + 雷 = 超载 (追加AOE)
冰 + 雷 = 超导 (减防)
风 + 任意 = 扩散 (全体施加元素)
```

元素反应、记忆异常和角色专属资源等系统，等基础三层流程稳定后再加入。

### 5.3 UI风格
- 半透明科技感面板
- 圆角 + 发光边框
- 流畅的卡牌划入/打出动画

## 6. MVP范围界定 (第1个月目标)

### ✅ MVP范围状态:
- [x] 基础卡牌类型 + 效果系统
- [x] 1个可玩角色（初始卡组10张）
- [x] 3种普通敌人 + 精英敌人 + 三层 Boss
- [x] 基础战斗状态机
- [x] 三层分支地图 + 路径选择
- [x] 商店 + 休息 + 事件节点
- [x] 药水和藏品后端
- [x] 控制台驱动的三层通关回归流程
- [x] 白膜 3D 战斗场景（UE5）
- [x] 运行时 Slate/UMG 卡牌和地图交互

> 注：这里的 `[x]` 只表示不依赖外部美术资源的可运行版本。正式角色模型、动画、卡牌立绘、UI 美术、特效和音频仍属于人工资源阶段，不能用白膜冒充。

### ❌ MVP不做 (后续迭代):
- 多角色
- 复杂角色差异化机制
- 存档系统
- 音效/BGM
- 完整动画系统
- 多语言

### 🎯 MVP完成标准:
> 在完成 Editor 编译和 Cook 后，一个玩家能够从启动 → 选择角色 → 爬塔 → 战斗 → 击败第三层 Boss，全程无阻断错误。

## 8. UE5 关键设计模式应用

| 模式 | 应用场景 | 面试可讲 |
|------|----------|----------|
| **命令模式** | 卡牌效果系统 | 解耦卡牌定义与效果执行 |
| **状态模式** | 战斗状态机 | 回合状态转换 |
| **观察者模式** | 事件系统(出牌/受伤) | UI更新、buff触发 |
| **对象池** | 卡牌GameObject复用 | 性能优化 |
| **GameInstance** | RunState、跨场景状态 | 局内状态管理 |
| **DataAsset** | 卡牌、敌人、节点配置 | 编辑器可配置数据 |
| **Subsystem** | 地图、战斗和资源服务 | 生命周期明确的服务 |

> 💡 **面试TIP**: 每种设计模式你都能讲出在SS3D里具体怎么用的，这就是最好的项目答辩。

# 记忆尖塔项目计划

版本：v0.1 MVP  
项目类型：单人卡牌 Roguelike  
目标平台：PC  
技术基线：Unreal Engine 5 + C++ + UMG

## 1. 项目定位

《记忆尖塔》是一款以 2D UI 操作为核心、以 3D 角色战斗演出增强反馈的单人卡牌 Roguelike。

玩家扮演被困在神秘空间中的角色，必须规划路线、完成战斗、构筑卡组并登上记忆尖塔顶层，获得离开的资格。

第一阶段先实现一个可完整通关的角色和三层尖塔。基础规则先采用成熟的卡牌爬塔范式，待完整循环稳定后，再加入《记忆尖塔》自己的角色机制和异常系统。

## 2. 已确定设计

### 2.1 世界观

- 尖塔是一个神秘的记忆空间。
- 玩家被困在其中，抵达塔顶后才能离开。
- 角色是这个空间中的不同存在，例如奥黛塔对应战士，木偶对应故障机器人。
- 卡牌是角色能力的呈现形式，不要求卡牌在世界中作为实体物品存在。
- 故事保持轻量，重点放在玩法、战斗反馈和关卡氛围。

### 2.2 游戏结构

一局流程：

```text
初始开局 -> 规划路线 -> 节点选择 -> 战斗与资源管理 -> 层末 Boss
        -> 进入下一层 -> 第三层 Boss -> 抵达塔顶并离开
```

总共三层。每层包含地图、普通战斗、奖励、商店、事件、精英、休息和 Boss 等节点。

### 2.3 表现形式

2D UI 负责高频操作和信息读取：

- 尖塔地图与路线选择
- 卡牌手牌、抽牌堆、弃牌堆
- 出牌与目标选择
- 生命、能量、护盾、状态、金币和资源
- 商店、事件、奖励、休息和结算界面

3D 场景负责战斗表现：

- 角色和敌人站场
- 普通攻击、技能、受击和死亡动作
- 卡牌效果对应的特效
- 敌人意图和 Boss 入场演出
- 战斗镜头和环境氛围

## 3. 第一角色：奥黛塔

奥黛塔是第一个完整实现的角色，定位为战士。第一版不引入复杂的角色专属资源，先验证基础卡牌战斗和完整爬塔流程。

### 初始状态

- 初始卡组：打击 x5、防御 x4、痛击 x1，共 10 张
- 每回合初始能量：3 点
- 默认每回合抽牌：5 张
- 回合结束后手牌进入弃牌堆
- 护盾和敌人行动按基础卡牌 Roguelike 规则结算
- 敌人行动意图在玩家回合可见

### 初始卡牌暂定规则

| 卡牌 | 数量 | 费用 | 效果 |
|---|---:|---:|---|
| 打击 | 5 | 1 | 造成基础伤害 |
| 防御 | 4 | 1 | 获得基础护盾 |
| 痛击 | 1 | 2 | 造成伤害并施加易伤 |

具体数值先作为可配置数据，按基础规则实现，后续通过测试调整。

## 4. 资源与节点

### 资源

- 卡牌：构筑战斗牌组。
- 藏品：提供持续被动效果，影响构筑方向。
- 金币：用于商店购买和移除卡牌。
- 药水：战斗中使用的一次性战力资源。

### 节点

| 节点 | MVP 功能 |
|---|---|
| 战斗 | 完成战斗，获得金币与卡牌奖励 |
| 奖励 | 选择卡牌、金币、药水或藏品 |
| 商店 | 购买卡牌、藏品、药水，移除卡牌 |
| 事件 | 提供带风险和收益的选择 |
| 精英 | 更高难度战斗，提供高价值奖励 |
| 休息 | 恢复生命或升级一张卡牌 |
| Boss | 完成当前层的最终挑战 |

## 5. MVP 完成标准

陌生玩家能够从启动游戏开始，完成以下闭环：

1. 选择奥黛塔并开始一局。
2. 查看三层尖塔地图并选择可用路线。
3. 完成普通战斗、精英战和 Boss 战。
4. 在战斗后获得并选择奖励。
5. 在商店购买或移除卡牌。
6. 使用休息点恢复生命或升级卡牌。
7. 通过事件节点作出选择并获得结果。
8. 管理藏品、金币和药水。
9. 击败第三层 Boss，显示通关结果。
10. 失败后能够重新开始一局。

## 6. 开发阶段

### 阶段 0：规则和工程基线

目标：让项目具备可持续开发的基础。

- 确认 UE5 项目可以打开、编译并进入 PIE（Play In Editor）。
- 整理 UE5 的 `Source`、`Content` 和模块目录。
- 确认数据驱动结构：卡牌、敌人、藏品、药水和节点。
- 写出战斗规则表和资源流转规则。
- 建立测试地图、GameMode 和调试入口。

完成标准：项目可运行，能够创建一个可重复的测试战斗。

### 阶段 1：地图生成与路径选择

目标：进入游戏后，玩家可以看到三层尖塔地图并选择一条合法路线。

- 使用 UE5 C++ 实现地图节点、地图层、节点连接和运行时地图状态。
- 生成三层地图，每层包含普通战斗、奖励、商店、事件、精英、休息和 Boss 节点。
- 保证起点、每层层末 Boss 和所有可显示节点之间存在可达路径。
- 记录当前所在层、当前节点和可选择的下一节点。
- 提供 `GetCurrentMap`、`GetAvailableNextNodes`、`SelectNode` 等后端接口。
- 先用日志或简单 UMG 列表验证路径选择，暂不要求正式美术。

完成标准：进入游戏后生成一张合法三层地图，玩家只能选择当前节点连接的下一节点，选择后状态正确推进。

### 阶段 2：战斗垂直切片

目标：先跑通一场完整战斗。

- 战斗状态机：玩家回合、敌人回合、胜利、失败。
- 抽牌堆、手牌、弃牌堆和洗牌。
- 能量、伤害、护盾和易伤。
- 打击、防御、痛击三种卡牌。
- 一个玩家、一个敌人和敌人行动意图。
- 2D 战斗 HUD 与基础战斗日志。
- 卡牌结算完成后触发 3D 动作和特效接口。

完成标准：玩家可以使用 10 张初始卡组击败敌人，也可能正常失败并重新开始。

### 阶段 3：单层爬塔循环

目标：让战斗成为可重复进入的地图循环。

- 地图节点数据和路线连接。
- 普通战斗节点。
- 战斗奖励界面。
- 角色生命在节点之间保持。
- 基础卡牌奖励和卡组查看。
- 一层地图与层末 Boss。

完成标准：玩家可以从层首进入地图，经过多个节点并击败第一层 Boss。

### 阶段 4：资源和节点系统

目标：补齐基本 Roguelike 决策。

- 金币和商店。
- 藏品系统。
- 药水系统和战斗内使用。
- 休息点和卡牌升级。
- 事件节点和事件结果。
- 精英敌人和精英奖励。
- 卡牌移除。

完成标准：玩家可以围绕路线、生命、金币和卡组质量作出有效取舍。

### 阶段 5：三层完整流程

目标：实现从开局到通关的完整版本。

- 三层地图生成。
- 每层的普通敌人组合。
- 每层 Boss。
- 至少一套可通关的奥黛塔卡组构筑路线。
- 通关、失败和重新开始流程。
- 基础局内统计和调试信息。

完成标准：能够稳定完成一局三层游戏，并正确处理胜利、失败和重开。

### 阶段 6：2D + 3D 表现整合

目标：让核心玩法具备可展示的视觉反馈。

- 角色和敌人的基础 3D 模型或可替换占位资源。
- 攻击、施法、受击和死亡动画。
- 卡牌打出时的动作触发。
- 伤害、护盾、易伤和药水的特效。
- Boss 入场和战斗结束演出。
- 2D UI 的状态同步、动画和响应式布局。

完成标准：所有关键操作都有明确的 UI 反馈和 3D 反馈，玩家能理解效果是否成功结算。

### 阶段 7：平衡和发布准备

目标：形成可交付的第一个试玩版本。

- 完成至少数轮完整游戏测试。
- 调整敌人生命、伤害、卡牌费用和奖励概率。
- 检查地图是否出现无路可走或收益失衡。
- 处理软锁、重复奖励、状态残留和场景切换问题。
- 优化 UI 可读性和输入反馈。
- 生成 PC 构建包并补充操作说明。

完成标准：陌生玩家能够独立理解操作并完成一局，游戏过程中没有阻断流程的严重错误。

## 7. 暂不纳入 MVP

- 木偶和其他可操作角色
- 多人模式
- 复杂剧情和长篇对话
- 复杂的记忆异常系统
- 存档和局外成长
- 多语言
- 完整配音、音乐和高级过场动画
- 大规模角色养成系统

这些内容等三层单角色流程稳定后，再根据实际试玩反馈决定优先级。

## 8. 关键设计决策顺序

开发时按以下顺序推进，避免表现工作掩盖规则问题：

```text
地图生成与路径选择 -> 战斗规则 -> 单层循环 -> 资源节点 -> 三层流程 -> 3D 表现 -> 平衡打磨
```

后续扩展也遵循同样原则：先确认玩法是否产生有意义的决策，再为它增加角色机制、动画和特效。
